## 摘 要

本文设计并实现了一款基于 ESP32-S3 的云边协同多模态 AIoT 智能状态监测与交互终端，面向**银发照护**与**工位健康管理**两大应用场景。系统采用"本地轻量检测 + 云端深度分析"的协同架构：终端侧基于帧差法实现实时运动与静止状态巡检，云端通过火山引擎豆包大模型完成图像语义理解、语音识别与合成，用户侧通过微信小程序实现远程监控、告警推送与多模态交互。

系统集成 OV2640 摄像头、I2S 全双工语音模块、SU03T 离线唤醒单元及 WS2812B 状态灯带，通过 EMQX Cloud MQTT 与火山引擎 TOS 对象存储实现数据链路贯通。针对嵌入式资源受限场景，采用 Linker `--wrap` 机制修复相机栈溢出、TLS 连接复用将全链路延迟从 25 秒压缩至 12 秒、有限状态机实现 12 状态优先级仲裁。本作品兼顾工程稳定性、场景实用性与系统完整性，验证了边缘端轻量化 AIoT 方案的可行性。

**关键词**：ESP32-S3；帧差法；云边协同；多模态交互；AIoT；有限状态机

## 1 作品概述

### 1.1 项目背景

随着老龄化进程加速与办公健康问题凸显，无人值守场景下的智能状态监测需求日益增长。传统监控方案存在隐私性差、带宽消耗大、交互方式单一等问题。本作品提出一种云边协同架构，在保障隐私的前提下实现低成本、低功耗的智能监测。

### 1.2 功能定位

本作品基于 **ESP32-S3 N16R8** 主控构建，核心设计理念为**"非必要不上传、弱网可运行、多模态交互"**，主要功能包括：

- **视觉巡检**：本地帧差法实时检测长时间静止、异常运动、区域活动等状态
- **云端分析**：异常事件触发抓拍，上传云端由大模型进行语义级判断
- **语音交互**：离线唤醒 + 云端 ASR/TTS，实现免接触自然语言对话
- **小程序管控**：实时遥测、告警追踪、场景切换、历史数据查询
- **离线容错**：断网状态下本地巡检不中断，恢复后自动补传

### 1.3 应用场景

| 场景 | 监测目标 | 告警策略 |
|------|---------|---------|
| 银发照护 | 老人长时间静止、异常跌倒姿态 | 拍照 + 云端分析 + 小程序推送 + 语音询问 |
| 工位健康 | 久坐超时、工位无人状态 | 语音提醒，不推送远端 |

## 3 核心算法：帧差法巡检

### 3.1 算法原理

终端在 QVGA（320×240）灰度模式下持续采集画面。将图像划分为 20×15 个 16×16 像素的子块，每块计算平均亮度作为特征值。与维护中的背景模型逐块比对亮度差，差值超过阈值（18/255）的子块标记为"变化块"。通过变化块占比（diffScore）判断当前画面的运动程度。

### 3.2 双场景参数配置

同一算法框架通过参数切换适配两种场景，具体参数如表 3-1 所示。

**表 3-1 双场景算法参数**

| 参数 | 银发照护模式 | 工位健康模式 |
|------|------------|------------|
| 灵敏度阈值 | 0.15 | 0.25 |
| 静止告警时长 | 5 分钟 | 90 分钟 |
| 异常确认帧数 | 3 帧 | 5 帧 |
| 巡检间隔 | 2 秒 | 5 秒 |

### 3.3 异常判定逻辑

系统支持两类独立异常检测路径：

- **运动异常**：连续 N 帧 diffScore 超过阈值，确认异常事件
- **长时间静止**：stillDurationMs 累计超过设定值，独立触发告警（不依赖运动帧）

针对不同场景采取差异化响应策略：
- 工位久坐：仅本地语音提醒，不推送小程序
- 银发异常：抓拍 → TOS 上传 → 豆包分析 → MQTT 告警 → TTS 语音询问

### 3.4 背景自适应更新

背景模型采用指数滑动平均（EMA）策略进行融合，blendFactor 取 0.03~0.05，正常情况下缓慢适应环境光线变化。为避免目标"融入"背景，设置两处冻结条件：
1. 检测到静止时长超过告警阈值的 1/3 时，暂停背景更新
2. 检测到剧烈持续运动时，暂停背景更新，防止运动物体被纳入背景模型

## 5 云端集成方案

### 5.1 火山引擎豆包大模型

- **视觉分析**：HTTP POST 提交图片 URL，返回一句话中文语义分析结果
- **LLM 对话**：历史告警上下文注入 Prompt，支持多轮对话记忆
- **ASR 语音识别**：WebSocket 实时流式传输 PDM PCM 数据，云端返回转写文本
- **TTS 语音合成**：WebSocket 流式下载 PCM 数据，I2S 本地边下边播

### 5.2 TOS 云对象存储

每次巡检抓拍生成 SVGA 800×600 分辨率 JPEG 图像，通过预签名 URL 上传至火山引擎 TOS。公开读 URL 经 MQTT 下发至小程序端供预览。系统维护 20 个预签名 URL 轮转复用，签名有效期 24 小时。

### 5.3 MQTT 通信协议

基于 EMQX Cloud 部署 MQTT Broker，各 Topic 定义如表 5-1 所示。

**表 5-1 MQTT Topic 定义**

| Topic | 传输方向 | 载荷内容 |
|-------|---------|---------|
| `device/status` | ESP → 小程序 | FSM 状态、当前场景、在线状态 |
| `device/alert` | ESP → 小程序 | 告警事件、严重级别、大模型分析结论 |
| `device/telemetry` | ESP → 小程序 | WiFi RSSI、TOS 上传状态、当日告警数 |
| `device/image_ref` | ESP → 小程序 | 巡检/抓拍照片公开 URL |
| `device/control` | 小程序 → ESP | 场景切换、抓拍、对话、OTA 等控制指令 |

## 7 关键技术难点与解决方案

### 7.1 cam_task 栈溢出问题

**问题描述**：ESP32 相机驱动库以预编译形式集成于 Arduino 框架中，`CONFIG_CAMERA_TASK_STACK_SIZE` 在 sdkconfig 中被固定为 2048 字节，编译选项无法覆盖。高负载场景下频繁触发栈溢出重启。

**解决方案**：采用 GNU Linker `--wrap` 机制，拦截所有对 `xTaskCreatePinnedToCore` 与 `xTaskCreate` 的调用。当检测到任务名为 `cam_task` 时，将栈大小参数从 2048 替换为 8192。该方案工作于链接层面，对预编译库同样生效，无需修改驱动源码。

### 7.2 全链路延迟优化

**问题描述**：各云端服务调用均需独立 TLS 握手（单次约 4.5 秒），端到端全链路延迟达 20~25 秒，交互体验较差。

**解决方案**：
- LLM HTTPS 连接 120 秒内复用，避免重复 TLS 握手（`chatClient_` 成员变量持久化）
- ASR WebSocket 连接优先复用，首轮失败后重建，正常路径零额外开销
- 音频 drain 循环内嵌 `g_mqtt.loop()`，阻塞间隙处理 MQTT 控制指令
- **优化效果**：全链路延迟从 20~25 秒降至约 12 秒

### 7.3 ASR WebSocket 会话状态管理

**问题描述**：火山引擎 ASR 服务在单轮话语结束后会话进入"已完成"状态，后续音频数据被丢弃，导致第二轮对话识别失败。

**解决方案**：遵循火山 ASR 协议规范，每轮对话开始前发送 `{"type":"input_audio_buffer.clear"}` 帧清除缓冲区，实现 WebSocket 长连接复用与会话状态重置。

### 7.4 模式切换传感器状态残留

**问题描述**：抓拍流程从 JPEG 模式切回灰度模式后，传感器寄存器状态残留，导致下次 `esp_camera_init(JPEG)` 阻塞超过 30 秒，触发看门狗重启。

**解决方案**：抓拍上传完成后执行 `ESP.restart()` 软重启，清空传感器状态。巡逻告警路径时间间隔充裕，重启开销可接受。

### 7.5 MQTT 消息长度截断

**问题描述**：PubSubClient 默认 `MQTT_MAX_PACKET_SIZE = 256` 字节，携带大模型分析文本的告警 JSON 约 350~500 字节，超出限制导致 `publish()` 静默失败。

**解决方案**：添加编译选项 `-DMQTT_MAX_PACKET_SIZE=1024`，扩容数据包缓冲区。

## 10 总结与展望

### 10.1 工作总结

本作品完成了从传感器数据采集、本地帧差法边缘计算、云端多模态 AI 分析到微信小程序交互面板的**全栈 IoT 系统闭环**。核心创新点如下：

1. **云边协同架构**：帧差法承担第一层实时筛选，云端大模型负责语义级理解，非必要不上传，显著降低带宽消耗与 token 成本
2. **双场景自适应**：同一算法框架通过参数切换适配银发照护（高灵敏度）与工位健康（宽松阈值）两类场景
3. **多模态交互**：视觉巡检 + 语音对话 + 小程序面板三位一体，覆盖不同使用习惯
4. **工程可靠性设计**：Linker wrap 栈修复、WDT 分级管理、OTA 双分区安全升级、离线降级策略

### 10.2 未来展望

- 引入本地 NPU 边缘推理模块，进一步降低云端依赖与延迟
- 优化 PSRAM 堆外内存分配策略，提升内存利用率
- 完善 SU03T 离线唤醒词体系，实现完全免接触交互
- 增加多设备组网能力，支持多终端协同监测
