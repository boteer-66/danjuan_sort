# 蛋卷交互策略——状态与告警分级

> 2026-05-29 | Claude + Codex 共识
> 核心原则：蛋卷不是报警器，是有分寸的陪护终端。平时少说话，每次出声都有理由。

---

## 一、三级行为

| 行为 | 说明 | 语音 | 小程序 |
|------|------|:--:|:--:|
| **观察** | 只记录 telemetry / TOS，不打扰 | 无 | 无推送 |
| **提醒** | 温和说一句，或小程序低优先级提示 | 轻声一句 | 小圆点 |
| **告警** | 高优先级，需要被感知 | 语音播报 | 强提醒 |

---

## 二、看护模态

| 状态层 | 状态 | 触发 | 行为 |
|------|------|------|:--:|
| **安全** | 安稳休息 | 长时间低活动，场景正常 | 观察 |
| | 正常活动 | 有人移动，豆包判断正常 | 观察 |
| **关怀** | 起夜活动 | 夜间（22-06）检测到活动，非跌倒 | 提醒（小程序） |
| | 夜间频繁起身 | 夜间多次活动 | 提醒（小程序） |
| | 离开关键区域 | 离床/沙发/房间 ROI | 观察→持续异常→提醒 |
| **异常** | 长时间静止 | >5min 无活动 | 观察→补充豆包确认→升级 |
| | 剧烈变化后静止 | 异常运动后突然不动 >60s | 提醒 + 豆包确认 |
| | 疑似跌倒 | 豆包视觉有相关特征但不确定 | 提醒 |
| **应急** | 跌倒/晕倒 | 豆包明确判断 | 告警 P0 |

**P0 告警动作**：语音 "检测到可能摔倒，已发送提醒" + MQTT `alert(severity:high)` + LED 红灯

**P0 冷却**：不强冷却，每 60s 重复一次直到小程序确认或状态恢复

**P1/P2 冷却**：同类事件 10-30 分钟冷却，避免刷屏

---

## 三、工位模态

| 状态层 | 状态 | 触发 | 行为 |
|------|------|------|:--:|
| **安全** | 专注工作 | 在岗 + 小幅活动 | 观察 |
| | 短暂离岗 | 离开 <30min | 观察 |
| **关怀** | 久坐风险 | 在岗 >90min | 提醒："起来活动一下？" |
| | 长时间离岗 | 离开 >30min（工作时间） | 提醒（小程序） |
| | 疑似疲劳 | 深夜在岗 / 豆包辅助判断 | 提醒（小程序） |
| **正向** | 恢复活动 | 久坐后起身 | 可选："活动一下挺好呀～" |

---

## 四、事件生命周期

```
local_suspect → capture → upload_tos → doubao_analyze
                                              ↓
                              P0: alert + 语音 + LED
                              P1: alert + 小程序
                              P2: telemetry only
                                              ↓
                              ack / resolved
```

---

## 五、蛋卷语音原则

1. **安全状态不开口**——安静观察，不刷存在感
2. **关怀状态轻声**——"注意脚下哦""起来活动一下？"
3. **应急状态果断但不吓人**——"检测到可能摔倒，已发送提醒，请确认是否需要帮助"
4. **正向反馈适量**——久坐后起身可以夸一句，但不要每件事都出声
